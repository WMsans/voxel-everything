# Voxel Everything — Water Voxels

**Date:** 2026-10-06
**Status:** implemented
**Start commit:** `40260c3` (`main`)
**Prior specs:** `2026-10-01-transparent-voxels-design.md` (the shell, thickness, front,
composite and resolve this builds on; read it first); `2026-08-23-material-system-design.md`
(the material table and atlas).

Water is a transparent material with its own shading: flowing wave normals, refraction,
per-channel absorption with a scatter colour, Fresnel and sun glint, shore foam, and an
underwater view. It does not flow as a fluid and has no physics: it is a ghost to colliders
and connectivity. It reuses the transparency pipeline end to end; the composite gains a liquid
branch.

---

## 1. Goals and non-goals

Goals:

- **Semi-realistic look.** Smooth depth absorption, soft refraction, smooth glint, subtle foam.
- **Looks like it flows downward.** Every sloped or vertical water surface shows ripples
  sliding downhill. A flat top has no downhill and keeps a slow, calm drift.
- **Shore foam** where the water is shallow.
- **Underwater view** with the camera inside water: distance fog, and the surface from below
  with Snell's window and total internal reflection.
- **Ghost water.** Bodies and the player pass through it; it never holds anything up and never
  becomes a falling island. The edit tool can still target and remove it.
- **Liquid is a kind, not a flag.** A future liquid (lava, swamp) is an enum value plus its
  shading, with no column change.
- **Ice and no-water scenes are bit-identical** to `main`.
- **Own module.** `BeautySettings`, `deferred.comp.glsl`, `shade.glslh`, `ssr.comp.glsl` and
  `outline.comp.glsl` are not edited.

Non-goals, decided explicitly:

- **Fluid simulation or flow.** Water stays where it was placed.
- **Caustics.**
- **Terrain-generated water** (lakes, sea level). The near-shell candidate scan cannot see a
  transparent material that a terrain stage produces (transparency spec §5 ceiling). Separate
  spec.
- **Vertex displacement.** The surface stays voxel-flat; waves live in the normals.
- **Underwater light shafts.**
- **A waterline split across the lens** (§6 ceiling).
- **Per-liquid tuning columns.** The wave, refraction and foam knobs are global (§8) while
  water is the only liquid.

## 2. Material data

`ve::MaterialDef` gains one column:

```cpp
enum class Liquid : uint8_t { none = 0, water = 1 };
Liquid liquid = Liquid::none; // which liquid shading and ghost rule apply; none = not a liquid
```

New row, appended after `bark` so no existing id moves:

| field | value | why |
|---|---|---|
| `name` | `water` | |
| `asset` | `"08"` | |
| `hardness` | 1.0 | removes at full brush size |
| `glow` | 0 | |
| `flat_albedo` | {0.03, 0.16, 0.20} | Doubles as the **scatter colour**, the deep-water body colour. Also what water looks like with `transparency.enabled = false`. |
| `transmit` | {0.50, 0.82, 0.88} | per metre; red dies first (about 0.25 left after 2 m, blue about 0.77) |
| `ior` | 1.33 | |
| `liquid` | `Liquid::water` | |

- `ve::material_liquid(uint16_t id)` returns the kind, failing soft to `none` for air, foliage
  and ids with no row, like the other lookups.
- `ve::material_table_glsl()` emits `const uint LIQUID_NONE = 0u;`, `const uint LIQUID_WATER
  = 1u;`, `const uint MAT_LIQUID[MATERIAL_COUNT]` and `uint mat_liquid(uint id)`,
  range-checked. The byte-exact generator test is re-recorded.
- "Is a liquid" means `mat_liquid(id) != LIQUID_NONE` everywhere. Only the composite's shading
  branch looks at which liquid it is.
- `tools/convert_materials.sh`'s `MATERIALS` array gains `water`, because
  `test_material_table.cpp` asserts that list equals the table. Its source pack has no water
  folder, exactly as it has no bark folder; layer 08 comes from its own generator, as layer 07
  comes from `convert_bark.sh`.
- **Liquids drop the `min_transmit` floor.** Ice's "never opaque" goal still holds for ice.
  Deep water fading to the scatter colour is the intended look.

**Textures.** `MaterialAtlas` refuses to load if any layer's map is missing, so water ships
five `08_*.png` maps generated by `tools/make_water_textures.gd` (headless Godot,
`Image.save_png`, no new dependency) and committed like the other materials:

- `08_basecolor.png`: flat scatter colour.
- `08_normal.png`: a 512² **tileable ripple normal map**. It is a sum of sines whose wave
  vectors are whole numbers of cycles per tile, so it tiles by construction. This is the
  texture §4 samples. A CC0 map can replace it later with no code change.
- `08_roughness.png`: flat low roughness. `08_ambientOcclusion.png`: flat white.
- No `08_glow.png` (the atlas packs a flat mask).

## 3. Ghost water: the solid view

The world now has three views of one field:

| view | transparent (ice) | liquid (water) | consumers |
|---|---|---|---|
| union | solid | solid | edit raycast (`world/raycast.cpp`), consolidation, override storage, near-shell candidate scan |
| opaque | air | air | brick atlas lattice, far-field opaque lattice (exists; transparency spec §3) |
| **solid** (new) | solid | **air** | colliders (`mesh_field.comp.glsl`, `mesh/mesh_chunk.cpp`), occupancy (brick_gen's occupancy classification), `connectivity/contact_refine.cpp`, island extraction (`island_extract.comp.glsl`) |

**Computed like the opaque view, never by carving afterwards.** Inside the op loop a liquid
ADD or PAINT op, or a volume sample whose material is a liquid, contributes nothing to the
solid accumulator. Carving the merged winner afterwards would dig a pit in the ground a water
op merely overlaps; the transparency branch measured exactly that failure (transparency spec
§11.2 item 1). GLSL in `field_ops.glslh`, C++ mirror beside `ve::apply_op_pair`.

- **Brick generation** already carries union and opaque. Occupancy is classified from the
  solid view instead of the union. Without liquid in the op stack the solid view equals the
  union, so no-water scenes classify identically.
- **Zero cost without water.** The terrain base field never produces a liquid, so the solid
  view equals the union unless an op or volume holds one. Each solid conjunct is written
  cheapest-first, with the geometric test guarding the `mat_liquid` lookup, as the opaque
  conjuncts are.
- **Island extraction strips liquid.** Island bytes are evaluated in the solid view, so an
  island never carries water.

Ceilings:

- **Override bricks** store union bytes. There the solid view falls back to the label rule
  (a liquid solid sample becomes just-outside air), so ground under consolidated water can sit
  up to one voxel (5 cm) off for collision.
- **Severing next to water.** A component is carved in 0.8 m occupancy cells and its island is
  stripped of liquid, so cutting a rock free inside a pond leaves a gap in the water of up to
  one cell beside it. Water does not flow, so the gap stays.

## 4. Wave normals: triplanar flow

`shaders/water_waves.glslh` exposes one function, read by the composite and the resolve:

```glsl
vec3 water_wave_normal(vec3 p, vec3 n_geo, vec3 ddx, vec3 ddy, float time); // world space
```

It samples water's own atlas layer of `material_surface_tex` (RG = tangent normal xy), which
the composite already binds. No new texture or binding exists for waves.

**Three projections,** weights `w = |n_geo|⁴`, normalised:

| projection | uv | motion |
|---|---|---|
| top (xz), `w.y` | `p.xz` | Two layers detuned in scale (about 5 m and 1.35 m tiles, a ratio of about 3.7 so the periods never align) and direction (about 110° apart), drifting slowly (about 0.04 and 0.09 m/s). The calm surface. |
| side X (`p.zy`), `w.x`; side Z (`p.xy`), `w.z` | horizontal, `p.y`, with v stretched ×2.5 so ripples read as streaks | Two layers both scrolling **downward** in world y, at `flow_speed` and 1.6 × `flow_speed`, at different scales. The falling surface. |

- **Blending.** The two layers within a projection are whiteout-blended
  (`normalize(vec3(a.xy + b.xy, a.z * b.z))`). The projections combine with whiteout triplanar,
  sign-corrected per side so a −X face is not mirrored. The final tilt is scaled by
  `wave_strength`.
- **Downward everywhere.** A side projection's uv moves toward −y in world space for every
  normal it is weighted on. On a 45° slope the top's drift cross-fades into the sides' fall,
  which reads as water tipping over an edge. Surface-nets normals are smooth, so there is no
  hard seam. Each projection is a constant scroll, so there are no flow-map phase resets and
  no pulsing.
- **The flow function is isolated.** The per-projection uv and scroll live in
  `water_flow_uv(p, n_geo, time, flow_speed)` inside the header, mirrored by
  `ve::water_flow_uv` so §9 can pin the downward rule on the CPU.
- **Anti-aliasing.** Compute shaders have no automatic derivatives. Every tap uses
  `textureGrad` with the pixel's world footprint (`ddx`, `ddy`, which the composite already
  derives) projected into that plane, so distant ripples mip down to calm. The glint widens its
  roughness with the footprint-to-tile ratio so distant sparkles do not strobe.
- **Cost.** A projection with weight under 0.01 is skipped: a flat pond pixel is 2 taps and a
  slope pixel at most 6.
- **Continuity.** Everything is world-space, so the normal is continuous across quads, chunks
  and the near/far shell seam. Islands never carry water (§3), so there is no island transform.
- **Time.** `time_seconds` from the same clock the grass and leaf scatter passes receive.

## 5. Composite: a liquid front seen from above

A new branch in `transparency_composite.comp.glsl`, taken when
`mat_liquid(front.w) != LIQUID_NONE`. The ice branch is byte-for-byte unchanged.

**The `lit` copy.** Refraction reads neighbouring pixels while the composite rewrites `lit` in
place, so `lit` is copied into a scratch target of the same format immediately before the
composite, on every frame where the shell drew. The CPU cannot tell which materials the shell
pages hold, so ice-only frames pay for the copy too (`ponytail:` marker; the upgrade is a
"liquid drawn" bit from the front pass).

Per liquid-front pixel, with `n` the wave normal from §4 and `n_geo` the stored front normal:

1. **Refraction.** Offset the lookup uv by `n`'s view-space xy × `refraction_strength` ×
   `saturate(thickness / 1 m)`, so shallow edges barely bend. **Reject** the offset sample and
   use the unrefracted pixel when either (a) the G-buffer depth there is nearer than this
   front, meaning a foreground object would leak in, or (b) that pixel has no liquid front,
   meaning shore above the waterline.
2. **Absorption from the refracted pixel's own thickness**: `T = transmit^thickness`, no floor.
   Reading thickness at the pixel the colour came from avoids the shore halo the tutorials warn
   about.
3. **Scatter body**: `body = scatter · (sky ambient + sun · sun-map visibility · k)`;
   `through = T · behind + (1 − T) · body`. Deep water becomes lit teal, not black.
4. **Fresnel**: Schlick, F0 = 0.02 from ior 1.33, on `n`; reflection is
   `sky_color(reflect(rd, n))`. SSR later blends real reflections over it where it hits
   (`ssr.comp.glsl` mixes its hit colour by its own Fresnel weight and leaves misses alone).
5. **Sun glint**: GGX specular, roughness about 0.05 widened by the footprint (§4), on `n` ×
   sun colour × sun-map visibility. Bloom picks the sparkles up.
6. **Shore foam**: `depth ≈ thickness · max(dot(v, n_geo), 0.05)` turns view-ray thickness into
   an estimate of vertical depth. `foam = (1 − smoothstep(0, foam_width_m, depth))` broken up by
   animated noise with a soft threshold, lit as Lambert under sun and sky, mixed over
   everything. Water meeting a wall gets a foam line along the wall.

Side faces have wave normals (§4), so refraction and glint apply there too. That is what makes
a water wall read as falling water and not a tinted pane.

## 6. The underwater view

1. **The front pass sees the exit face, for liquid only.** `ShellRasterPass` builds a second
   front pipeline with culling off. It is chosen only when the camera's sampled material is a
   liquid. Outside water, and inside ice, the current back-face-culling pipeline runs unchanged.
   The nearest fragment still wins. The stored normal still points out of the medium, so the
   composite tells an exit face by `dot(n_geo, v) < 0`. No new encoding.
2. **Pixels with no front** (ground and walls underwater): thickness is the distance to the
   opaque hit, because of the existing virtual front at 0.
   `T = transmit^thickness`; `out = T · behind + (1 − T) · scatter_lit`, where `scatter_lit` is
   §5 step 3's body. Distance goes teal, then into the scatter colour.
3. **The surface from below.** `n` is the wave normal flipped to face the camera.
   `r = refract(rd, n, 1.33)`.
   - **Inside Snell's window** (`r` non-zero): the above-water lit pixel, with §5 step 1's
     offset and rejection rules, or `sky_color(r)` where there is sky. Schlick brightens toward
     the window's edge.
   - **Total internal reflection** (past about 48.6°): `scatter_lit`. SSR replaces it with real
     reflected underwater geometry where it hits (item 4).
   - Then fog for the water between camera and surface: `T = transmit^front.z`, mixed toward
     `scatter_lit`.
4. **The resolve writes the camera-facing normal** for an exit face. SSR then reflects downward
   off the underside, which is total internal reflection of the pond floor wherever SSR finds a
   hit.
5. **Inside ice** keeps today's flat-tint path.

Ceilings:

- **Camera on the surface.** Inside is a single point sample at the camera, so crossing the
  surface switches the whole frame at once. There is no waterline split across the lens.
- **Water through water from below.** Only the nearest exit face is shaded. A second body seen
  through the first surface contributes thickness only, the per-layer limit ice already has.

## 7. The resolve

`shell_resolve.frag.glsl` writes `water_wave_normal(...)` for a liquid front, flipped to face
the camera for an exit face, so SSR reflections ripple and flow with the surface and outlines
follow it. Ice fronts are written exactly as today. Gloss stays `SHELL_GLOSS` (0.9) for every
transparent material. The pass gains a push block (camera footprint, `time_seconds`, the
`water` vec4) and bindings for the material surface array and the camera UBO.

## 8. Module, settings, failure handling

- **Module:** `extension/src/water/`: `WaterSettings`, its store (the `transparency_settings`
  pattern), and the C++ mirrors (`ve::water_flow_uv`, the solid-view op rule).
- **Integration:** a few lines in `VoxelFrame::render_pre_opaque` (the copy, push values, the
  liquid front pipeline choice) and the pass registry. `--water=R` in `demo/benchmark.gd`, the
  twin of `--ice=R`, applied before the first streamed frame as `--transparency=` is
  (transparency spec §11.2 item 7). The material picker lists water with no change, because it
  reads `material_table()`.

`WaterSettings`, all read every frame:

| setting | default | meaning |
|---|---|---|
| `wave_strength` | 1.0 | Tilt multiplier on the wave normal. 0 = mirror-flat. |
| `flow_speed` | 0.6 m/s | Downward scroll on sloped and vertical faces. The top drift is fixed and slow. |
| `refraction_strength` | 0.03 | Screen-uv offset at full tilt. 0 = no refraction. |
| `foam_width_m` | 0.3 | Water depth where shore foam fades out. 0 = no foam. |

The composite push block gains `water` (vec4 of the four settings) and `time_seconds` (a free
lane of `params`).

**Failure handling.** A failed copy, composite or resolve cancels its stage; that frame shows
no water shading and the frame continues. It is never aborted. A missing `08_*.png` fails the
atlas, as for any material today; the generator's outputs are committed. **Ghost behaviour is
independent of `transparency.enabled`:** with rendering off, water draws opaque in its scatter
colour and is still pass-through.

Characterization first.

1. **Pins before any edit.** `tests/test_transparency.gd`, the ice goldens and the
   no-transparent goldens stay bit-identical after every task. `test_frame_shipped_golden.gd`

   - Material table generator, byte-exact, with the `Liquid` enum and `mat_liquid`.
   - **Solid view:** a water sphere added on a meadow leaves the ground intact (no pit) in the

   - Occupancy classifies a water-only region as empty. Island extraction strips water.
   - **Flow:** `ve::water_flow_uv` moves each side projection's uv toward −y over time for

   off as the transparency fixture does (transparency spec §11.2 item 8):

   - A severed floating water blob does not become an island.
   - Shallow water shows tinted ground. Deep water approaches the scatter colour and may fall
     below `min_transmit`.
   - A pillar in front of water keeps its pixels unchanged (no refraction leak).
   - Water pixels change between two capture times; pixels away from the water do not.
   - Camera underwater: fogged but not black; far ground more teal than near; looking straight

## 12. Deviations and measurements recorded during implementation

### 12.1 The plan's deviations, decided while planning

1. **The flow rule is tested by executing `shaders/water_flow.glslh` natively**, through a small C++ shim, as `extension/tests/test_grass_tilt_shader.cpp` does for the blade tilt. There is no `ve::water_flow_uv` C++ mirror: a mirror can drift, the executed shader cannot. The pure uv math lives in `water_flow.glslh`; the texture sampling lives in `water_waves.glslh`.
2. **The resolve is not edited.** The composite writes the camera-facing shading normal into `front.xy` (the front target gains storage usage), and the existing resolve already copies `front.xy` into the G-buffer surface. Spec §7's "resolve evaluates the waves" would sample the waves twice per pixel.
3. **The triplanar blend reuses `triplanar_normal()` from `shaders/common.glslh`**, the whiteout blend the terrain already uses, which carries the geometric sign per projection. A negative face's ripple texture is mirrored, exactly as terrain textures are; for a ripple map this is invisible.
4. **Brick generation and brick marking gate the second evaluation.** They evaluate the solid view only when the brick's filtered op list holds a liquid ADD/PAINT or any volume op (`op_may_hold_liquid`); otherwise they apply the label rule to the union sample. Without such an op the two are equal by construction, so the CPU mirror (which always evaluates) matches exactly.
5. **Island normals at a liquid boundary.** Where the masked union and the masked solid view disagree, the island voxel stores `0x8080`, the existing "no stored normal" marker, and the marcher shades it from the R8 lattice. The union gradient there belongs to the water.
6. **`mesh/mesh_chunk.cpp`'s `chunk_has_surface` keeps the union.** It is a conservative residency probe for collider chunks; a chunk holding only water is built and meshes zero triangles.
7. **Snell's window shows the lit pixel**, which already holds deferred's sky, rather than `sky_color(r)`.
8. **Shading constants pinned here:** scatter picks up `0.35` of the sun; the glint is capped at `64`; foam albedo `0.9`, foam opacity `0.85`.
9. **Two §9 GPU tests take a more direct form.** "A physics ray passes through water" is tested on the collision lattice itself (`debug_mesh_lattice_diff` reports no surface for a water ball, and a surface for the same ball in rock), because the gdUnit fixtures run with physics off. "A severed floating water blob does not become an island" is tested at its cause: the blob's cell is `kCellAir` in the GPU occupancy grid and in `cell_state_field`, so it can never be a component.

### 12.2 Deviations the plan did not foresee

1. Task 6 (controller-accepted): `tests/test_water.gd`'s frames test uses a stream+render
   settle fixture rather than the brief's literal loop, and the determinism sub-check pins
   `foam_width_m = 0.0` — the brief's literal code was flaky by construction (water_foam
   keys noise to time). The spec's Review Focus 4 (finite, deterministic frames) is what the
   changed code tests.

### 12.3 Cost

Interleaved A/B/A legs, `--near-scale=0.40`, sphere `r=3` placed at the same spot in all
three legs ((28.51491, 56.37516, 28.51491)). Steady leg (`--benchmark`) numbers, ms:

| leg | p50 | p95 | p99 | frame_avg | max |
|---|---|---|---|---|---|
| A1 (ice) | 31.94 | 33.33 | 33.49 | 32.26 | 38.48 |
| B (water) | 32.10 | 33.33 | 33.33 | 32.47 | 34.54 |
| A2 (ice) | 31.94 | 33.33 | 33.33 | 32.33 | 37.90 |

Delta (B − mean(A1, A2)): p50 +0.16, p95 +0.00, p99 −0.08, frame_avg +0.18, max −3.65.
A/A spread (|A1 − A2|): p50 0.00, p95 0.00, p99 0.16, frame_avg 0.07, max 0.58.
Quotable where |delta| > A/A spread: p50, frame_avg, and max nominally (p99's |delta| 0.08 is
below its A/A spread 0.16; p95's is zero), so neither p99 nor p95 is quotable; in practice
the A/A spread on max is a single-frame outlier, so the honest summary is that water's
shading cost is +0.2 ms frame time at this size and resolution — within display-quantised
(1/60s-grid) noise of an M1 — and no quotable regression. GPU pass timings were invalid on
this machine (Metal does not surface per-pass timestamps to Godot), so frame time only.
